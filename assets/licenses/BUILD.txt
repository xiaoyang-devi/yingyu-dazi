Source files and builds
Kokoro.js: extract kokoro-source.tar.gz, enter its kokoro.js directory, then npm ci and npm run build with compatible Node/npm. This reproduces the upstream build flow using its package-lock and Rollup config. The parent LICENSE is present. @huggingface/transformers@3.5.1: extract transformers-v3-source.tar.gz, install from package-lock with npm ci, and use the package build script. The full, exact upstream source archive URLs and the SHA-256 of the originals are also in sources.json. These two archives select the code, lockfiles and build scripts and omit unrelated demo media.
phonemizer.js: extract phonemizer-source.tar.gz at npm's published gitHead 6835144b7ee9043129222549c1ed2f6a27216278; use npm ci and npm run build as instructed by its package.json. Its repository contains the actual embedding source and eSpeak-generated JavaScript/data used in this package.
eSpeak NG: espeak-source.tar.gz contains C sources, dictionary and phoneme inputs, the full Emscripten port with Makefile, glue, and upstream build instructions in emscripten/README.md. From its upstream checkout the English target uses the Emscripten toolchain and the commands in that README. The published phonemizer package does not identify the precise C-compiler revision or even the eSpeak C gitHead. We independently compared every directly comparable language/voice text resource: all 328 matched this C/data checkout at 0dfd1d77dd7f96ef1ea6856c9fa5cfac01599582 byte-for-byte. The other five dictionary/phoneme artifacts are generated binary data. This identifies the verified source/data match and the exact JS wrapper; it does not establish that the C-engine binary was built byte-for-byte from that commit. Upstream provenance discussion: https://github.com/xenova/phonemizer.js/issues/6
